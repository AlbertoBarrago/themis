Humans lay down the law.

Themis is a format and a CLI for spec-driven agentic development. You write a spec.md with decisions and acceptance criteria and approve acceptance tests that lock it into a contract. Coding agents then iterate until a single verifier passes. The point is not generating a plan; it is guaranteeing convergence.

The law and the work

Themis is the Titaness of divine law and order: she lays down what is right, and her scales weigh what is done against it. The format separates the two.

The law, owned by humans
The spec (decisions and acceptance criteria) and the locked acceptance tests that turn it into an executable contract. Agents read it and never change it.
The work, produced by agents
The implementation, iterated until the verifier passes. What an agent claims never counts; only the verifier's exit code moves a task.

How it works

Three human gates, and only three. Everything else is decided by the verifier.

  1. spec.md

    You write decisions and acceptance criteria. themis check reports every problem with line, column and field.

  2. themis init

    Generates the judge: the verifier and the guard. No AI involved.

  3. themis plan

    A planner agent proposes the task graph, checked mechanically against the spec, plus questions about ambiguities.

    Gate 1 · approve plan
  4. themis tests

    A test-author agent writes the acceptance tests. You read them, edit them if needed, and lock them by digest.

    Gate 2 · approve tests
  5. themis run

    Per task, in its own git worktree, no human involved: worker edits, Themis verifies, a reviewer reads the diff, Themis merges and verifies again.

  6. themis retro

    A retro agent proposes changes to the agents' instructions, each citing the evidence from the run it addresses.

    Gate 3 · approve retro

The second gate matters most: once the tests are locked, “done” means .themis/verify.sh exits 0, and nobody needs to ask you again.

A spec is a Markdown file

YAML frontmatter, a ## Decisions section the agents must respect, and one ## AC-<n> section per acceptance criterion. Each criterion is a node of the task graph and a group of tests named AC-<n>: ....

SPEC_FORMAT.md is normative and usable without the CLI: a team can write specs, lock tests and run a verifier by hand. 

---
themis: 0.1
stack: node-ts
verify: [typecheck, lint, unit, acceptance]
limits: { max_iterations: 5, parallel: 3 }
models: { planner: strong, worker: fast, reviewer: strong }
---

# Greeting service

## Decisions
- `src/greet.ts` exports `greet(name: string): string`.

## AC-1 Greets by name
Depends: none
- Given the name "Ada"
- When greet is called
- Then it returns "Hello, Ada"

What Themis guarantees

One judge

Only the verifier's exit code moves a task. Themis runs it itself, in the task's worktree and again after merging.

An immutable contract

Every locked file is recorded by SHA-256. Any change fails the guard, and so does any .only(, @ts-ignore, as any or linter suppression added after the lock.

A reviewer against scope creep

A read-only reviewer judges the committed diff. Implementing a neighbouring criterion, faking behaviour or breaking a decision costs an iteration.

Agent output is never trusted

Plans, tests, verdicts and retrospective proposals are validated mechanically before they reach you or the repository.

Semantic exit codes

0 pass, 1 the code is wrong (fix and retry), 2 the environment is broken (stop, a human is needed). The same convention everywhere.

Isolation when you want it

With --executor lima, agents, git, npm and the verifier run in a dedicated VM that only sees your workspace folder.

Quick start

Node.js 22+, git, and Claude Code logged in. Not on npm yet: install from a clone with npm install && npm run build && npm link.

$ themis check                 # validate spec.md
$ themis init                  # verifier, guard, agent roles
$ themis plan && themis approve plan
$ themis tests && themis approve tests
$ themis run                   # until every task is done
$ themis status
$ themis retro && themis approve retro

Inspiration

“A final tip: probably the most important thing to get great results out of Claude Code -- give Claude a way to verify its work. If Claude has that feedback loop, it will 2-3x the quality of the final result.”

Boris Cherny, creator of Claude Code, January 2026

Themis takes that idea to its conclusion: make the verifier the only judge, lock what it verifies, and turn the mistakes of every run into better instructions for the next one. More in the wiki.
