Humans lay down the law.
Agents do the work.
One verifier judges.

Themis is a format and a CLI for spec-driven agentic development. You write a spec.md with decisions and acceptance criteria, then lock acceptance tests that turn it into a contract. Coding agents iterate until a single verifier passes. The point is not generating a plan; it is guaranteeing convergence.

The idea

The law and the work

Themis is the Titaness of divine law and order: she lays down what is right, and her scales weigh what is done against it. The format keeps the two apart.

Owned by humans

The law

The spec, with its decisions and acceptance criteria, and the acceptance tests that turn it into an executable contract. Once locked, agents read it and never change it.

Produced by agents

The work

The implementation, iterated until the verifier passes. What an agent claims never counts: only the verifier's exit code moves a task forward.

How it works

Three human gates, and only three

You decide what and when it is done. Agents decide how. The verifier decides whether they did it.

  1. 1

    spec.md

    You write decisions and acceptance criteria. themis check reports every problem with line, column and field.

  2. 2

    themis init

    Generates the judge: the verifier and the guard. No AI involved.

  3. 3

    themis plan

    A planner agent proposes the task graph, checked mechanically against the spec, and raises questions about ambiguities.

    Gate 1 · approve plan
  4. 4

    themis tests

    A test-author agent writes the acceptance tests. You read them, edit them if needed, and lock them by digest.

    Gate 2 · approve tests
  5. 5

    themis run

    Every task in its own git worktree, in parallel where the graph allows, with no human involved until the end.

  6. 6

    themis retro

    A retro agent proposes changes to the agents' instructions, each citing the evidence from the run it addresses.

    Gate 3 · approve retro

The second gate matters most. Once the tests are locked, “done” means .themis/verify.sh exits 0, and nobody needs to ask you again.

Inside a run

Every iteration, the same loop

Each task works on its own branch, up to limits.parallel at once. An iteration that fails costs one of limits.max_iterations, and the next one starts with the reason.

  1. 1

    Sync

    The worktree takes in what was merged meanwhile.

  2. 2

    Work

    The worker agent edits the code for this task only.

  3. 3

    Verify

    Themis runs the verifier itself. The agent's claims do not count.

  4. 4

    Review

    A read-only reviewer rejects scope creep and faked behaviour.

  5. 5

    Merge

    Merged and verified again; Themis undoes its own merge if it fails.

State is saved after every step: interrupt with Ctrl-C and run again to resume. Themis never commits your changes and never rewrites history it did not just write.

The format

A spec is a Markdown file

YAML frontmatter, a ## Decisions section the agents must respect, and one ## AC-<n> section per acceptance criterion.

Each criterion is a node of the task graph, the unit of work for an agent, and a group of tests named AC-<n>: ....

SPEC_FORMAT.md is normative and usable without the CLI: a team can write specs, lock tests and run a verifier by hand.

The verifier

One judge, three answers

Every command and the verifier itself share one convention, so a loop always knows whether to retry or to stop.

0

Pass

The criterion is satisfied. The task moves on.

1

The code is wrong

The agent reads .verify.log, fixes the implementation, retries.

2

The environment is broken

The loop stops. A missing tool or a corrupt lock needs a human.

Guarantees

Built so that agents cannot cut corners

One judge

Only the verifier's exit code moves a task. Themis runs it in the task's worktree, and again after merging.

An immutable contract

Locked files are recorded by SHA-256. Any change fails the guard, and so does any .only(, @ts-ignore or as any added later.

No scope creep

A read-only reviewer judges every diff. Implementing a neighbouring criterion or faking behaviour costs an iteration.

Output never trusted

Plans, tests, verdicts and retrospective proposals are validated mechanically before they reach you or the repository.

Runs that learn

A retrospective turns the mistakes of each run into better instructions, citing the evidence, approved by you.

Isolation on demand

With --executor lima, agents, git and the verifier run in a dedicated VM that only sees your workspace.

Quick start

From spec to merged code

You need Node.js 22+, git and Claude Code logged in. Themis is not on npm yet; install it from a clone:

npm install && npm run build && npm link

The Getting Started walkthrough runs a ready-made spec through the whole loop. Tried it? Tell us how it went with a run report.
