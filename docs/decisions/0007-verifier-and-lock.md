# 0007. Generated verifier, guard and lock file

Status: accepted (2026-10-06)

## Context

`SPEC_FORMAT.md` section 6 defines the verifier contract. M1 generates it for `node-ts`; M3
writes the lock it reads, so the lock format must be fixed now.

## Decision

### Files

`ordito init` writes, under `.ordito/`:

- `verify.sh`: bash, self-contained, enabled steps baked in from the spec frontmatter.
  Regenerated by `ordito init --force`.
- `guard.mjs`: dependency-free Node script for the guard step (Node is always present in
  `node-ts`, and `shasum`/`sha256sum` differ across platforms).

Both are part of the locked contract.

### Steps and exit codes

| Step        | Command                                                                     | Exit 2 when                                   | Exit 1 when                       |
| ----------- | --------------------------------------------------------------------------- | --------------------------------------------- | --------------------------------- |
| preflight   |                                                                             | `node` missing, `node_modules` missing, bad `TASK_ID` |                          |
| guard       | `node .ordito/guard.mjs`                                                    | lock corrupt, git needed but unavailable       | digest mismatch, extra or missing locked file, forbidden marker |
| typecheck   | `node_modules/.bin/tsc --noEmit`                                            | binary missing                                 | non-zero exit                     |
| lint        | `node_modules/.bin/biome check .`                                           | binary missing                                 | non-zero exit                     |
| unit        | `vitest run --exclude 'tests/acceptance/**' --passWithNoTests --retry=0`    | binary missing                                 | non-zero exit                     |
| infra       | `docker compose config -q`, then `docker compose up -d --wait`              | `docker info` fails, `up` fails                | no compose file, invalid compose file |
| migrate     | `npm run migrate`                                                           |                                                | script missing, non-zero exit     |
| acceptance  | `vitest run tests/acceptance --retry=0 [-t '^AC-<n>:']`                     | lock missing ("contract not locked")           | non-zero exit                     |

Compose file and migrations are written by agents (the planner's `setup` task), so their
absence or a failing migration is a code problem (`1`). This matches `SPEC_FORMAT.md` 6.3,
as amended in M1. A broken Docker daemon is an environment
problem (`2`).

Every step runs with `NO_COLOR=1 FORCE_COLOR=0 CI=1`. On failure `.verify.log` contains the
step, exit code, command and the last `ORDITO_LOG_LINES` (default 200) lines of output with
ANSI sequences stripped. On success `.verify.log` is removed.

### Guard

- Lock absent: digest checks are skipped (acceptance will exit `2` anyway); markers are scanned
  in every source file.
- Lock present: every locked file must match its digest; any file under a locked directory
  that is not in the lock is a violation. If the lock records a `base` commit, markers are
  scanned only in lines added since `base` (tracked changes via `git diff`, plus untracked
  files); otherwise in every source file.
- Scanned files: `.ts .tsx .mts .cts .js .jsx .mjs .cjs`, excluding `node_modules/`, `dist/`,
  `.ordito/`.

### `.ordito/lock.json` (written by `ordito approve tests` in M3)

```json
{
  "ordito": "0.1",
  "lockedAt": "2026-10-06T12:00:00.000Z",
  "base": "<git commit sha or null>",
  "dirs": ["tests/acceptance"],
  "files": { "tests/acceptance/ac-1.test.ts": "<sha256 hex>", "spec.md": "<sha256 hex>" }
}
```

## Consequences

- Markers inside strings or comments are also flagged; accepted for the MVP.
- With `-t '^AC-<n>:'`, a criterion with no tests would pass vacuously; `ordito approve tests`
  (M3) must refuse to lock unless every criterion has at least one test.
